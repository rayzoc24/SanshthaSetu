# Engineering Rules (SanshthaSetu)

These rules apply to every AI tool working in this project.
Violations must be flagged before writing any code.

---

## API

- Routes are unprefixed. Module 0 pattern: `/auth/login`, `/health`, `/admin/ping`. New routers mount at `/aph`, `/readiness`, `/applications`, etc. No `/api/v1` prefix.
- Naming: `POST /resource`, `GET /resource/{id}`, `PATCH /resource/{id}`, `DELETE /resource/{id}`.
- Every error response shape: `{ "detail": "<human-readable message>" }` (FastAPI default). Never return a bare string.
- Status codes: 200 success, 201 created, 400 bad input, 401 unauthenticated, 403 wrong role, 404 not found, 422 validation error (automatic), 500 unexpected.
- `GET /health` — no DB call, always 200. `GET /health/db` — `SELECT 1`.

## Permissions

- Every non-public endpoint calls `require_roles([...])` as a FastAPI dependency.
- `require_roles` is a synchronous `def`. It reloads the user from the DB and rejects inactive users.
- College Admin: queries filtered by `users.institution_id`. Never return rows for other institutions.
- Regional Officer: queries filtered by `users.region`. Never return rows for other regions.
- Every new endpoint requires a test with the wrong role that expects 403.
- Use `HTTPBearer(auto_error=False)` and raise 401 manually when the token is missing or malformed. Never rely on FastAPI's automatic 403 from `auto_error=True`.

## Audit

- `record_audit` commits in its own independent session so audit rows persist even when the request fails.
- Call `record_audit` for: login (success and failure), user create/deactivate, APH publish, application submit, every stage transition, EVC report submit, compliance item update.
- `application_history` is written only through `move_application`. Never insert directly.
- `audit_log` and `application_history` are append-only. No UPDATE or DELETE. Database triggers enforce this.

## Database

- One Alembic migration per module. Migration file named `{seq}_{module_slug}.py`.
- Never edit an applied migration. Add a new one.
- All primary keys are UUIDs (`server_default=gen_random_uuid()`).
- Stage names come from the `workflow_stages` table. Never hard-code stage names in Python.
- Extend stub tables from Module 0 only through new migrations, never by altering `0001_initial_schema.py`.
- `set_updated_at` trigger on all tables except `audit_log` and `application_history`.
- `BEFORE TRUNCATE` protection on `audit_log` and `application_history`.

## AI (Gemini)

- All Gemini structured output must pass a Pydantic schema. On validation failure: log and surface to admin; never silently accept partial data.
- Extracted content is stored as `draft` status. Only a Main Admin can publish.
- Cache successful extractions keyed by a sha256 content hash of the page text used. A Main Admin may force re-extract only while the version is still `draft` (`POST /versions/{id}/extract?force=true`); forced runs replace all draft rules and are audited.
- Never auto-publish anything generated by AI.
- Every AI-generated value shown in the UI must be labeled **AI-suggested**.
- Send only public APH text and synthetic documents to Gemini (free-tier data policy).

## Free-Tier Constraints

- No Celery, no Redis, no separate worker process.
- Long-running work (extraction, compliance checks) runs as a FastAPI `BackgroundTask`; the UI polls a status field on the relevant DB row.
- `/internal/run-checks` (secret key header) is the source of truth for compliance checks and must be idempotent. APScheduler inside the API process is optional but must not duplicate work if both fire.
- The Render service may sleep. Code must tolerate cold starts and retries.
- Neon DB: 0.5 GB limit. Keep seed rows minimal.
- Gemini free tier: cache every result keyed by content hash; never call the API twice for the same input. Every Gemini call uses a timeout (30 s) and at most 2 retries with exponential back-off.

## Uploads and Background Work

- Validate file uploads: check PDF magic bytes (`%PDF`), reject if missing; maximum file size 25 MB.
- Long-running work (PDF extraction, compliance runs) executes as a `BackgroundTask`; the endpoint returns immediately with a job/status reference. The UI polls the status field until `done` or `failed`.
- Store all timestamps in UTC in the database. Display in IST (UTC+5:30) in the frontend.
- Never log secrets, tokens, or raw authorization headers. Redact before writing to logs or audit entries.

## Frontend

- No hard-coded colors, fonts, or spacing in components. Use Tailwind theme tokens / CSS variables only.
- Government theme (UX4G / GIGW tokens) applied in Module 0.5; components must be ready to receive it without changes.
- No mock data. Every screen calls the real API via TanStack Query + Axios.
- Accessibility basics: semantic HTML, visible focus ring, minimum contrast ratio 4.5:1, form labels linked to inputs.

## Testing

- Tests run against real Postgres (`TEST_DATABASE_URL` Neon branch or local Docker). No SQLite, no mocks.
- Session fixture: `alembic downgrade base` → `alembic upgrade head` once per session, then committed seed rows.
- Test isolation: savepoint (nested transaction) pattern inside each test.
- Override `SessionLocal` so `record_audit` uses the test database.
- Audit assertions filter by a unique email in `detail`; never count all rows.
- Unit test (pytest): readiness comparison logic, workflow transition validation, permission checks.
- Manual / Swagger test: file upload, Gemini extraction, email delivery, deployment smoke test.

## Git

- One task per commit. Commit message format: `[M{module}.{task}] <imperative description>`.
- Never commit `.env`. Always provide `.env.example`.
- Do not rename or delete existing files, tables, or endpoints without asking first.
